## Concrete comparison

| Area | Classification | Finding |
| --- | --- | --- |
| Linux and m1n1 base pins | Identical | Both projects pin the revisions above; no newer base explains their difference. |
| Kernel patch strategy | J71b-specific / unresolved | iOMARCHY rebuild applies no kernel patches and uses allnoconfig plus kernel.fragment. Orchard applies device patches including T8010 DT/driver work, Wi-Fi/Bluetooth and explicit NVMe write opt-ins. Do not import the set into J96. Individual generic hunks still require review. |
| Page size / CPUs | J71b-specific | Historical resolved J96 config uses ARM64_4K_PAGES=y and NR_CPUS=2; Orchard uses ARM64_16K_PAGES=y and NR_CPUS=8. Retain 4 KB for A8. |
| Effective config | Reusable method; different input | Historical manifest contains a resolved J96 config. J96 disables BLOCK, NET, MODULES, PCI and DRM; enables FB_SIMPLE, DWC2 and ACM. Orchard enables BLOCK, NET, MODULES, PCI, DRM and NCM, has NVMe=m, and does not enable FB_SIMPLE. Both enable DWC2, ACM and RD_GZIP. Current effective J96 config must be regenerated with the actual toolchain. |
| J96 DT chain | Reusable existing board source | t7000-j96.dts → t7000-mini4.dtsi → t7000.dtsi, t7000-common.dtsi, t7000-handheld.dtsi; t7000.dtsi includes t7000-pmgr.dtsi. Header dependencies include GPIO, IRQ/AIC, PHY, Apple pinctrl and input bindings. Compatible is apple,j96 / apple,t7000 / apple,arm-platform. |
| DT production | J71b-specific | Orchard starts from t8010-j71b-devbase.dtb and applies PCIe/Wi-Fi, alias, battery, Bluetooth and GPIO/power overlays, checking an expected hash. J96 should initially compile its existing DT without those overlays. |
| Loader handoff | Unresolved | J96 framebuffer starts disabled with zero reg and omitted format properties; memory size, CPU release addresses and USB PHY tunables also expect loader input. No runtime populated DT was recovered. Do not guess framebuffer addresses/stride/format or diagnose a kernel failure from these placeholders alone. |
| Payload order | Reusable with compatibility gate | Both order loader → chosen.bootargs → DTB → compressed kernel → initramfs. iOMARCHY directly appends gzip cpio; Orchard inserts ASCII m1n1_initramfs plus little-endian 32-bit compressed size before the archive. Verify selected binary understands framing before using Orchard assembly. |
| Boot arguments | Different policy | J96 includes ttySAC0/tty0, earlycon, loglevel=8, rdinit=/init, panic=0 and clock/power-domain ignore flags plus per-attempt j96.session. Orchard recovery uses j71b.recovery=1, loglevel=7, fbcon=map:9 and disabled VT cursor. Do not copy J71b display suppression into initial observable J96 boot. |
| /init and USB | Reusable concepts | J96 mounts RAM filesystems, binds ACM and ties gadget serial to the boot session; no network/storage. Orchard checks apple,j71b, sets up NCM+ACM, DHCP, provisioned SSH and PID-1 handoff. Its identity/runtime paths are board-specific. Start with serial-only J96 execution proof. |
| CLI | Reusable contract; implementation missing | Adapter contract covers read-only discovery, validated identity/resume state, bounded boot, pinned connection, private ADT/mixin and firmware inputs. Registry currently supports only j71b. J96 needs its own adapter and recovery identity contract after RAM boot; changing only the registry would falsely advertise support. |
| Desktop | Deferred | minimal-linux is the reference before omarchy-a. No J96 GPU, touchscreen or desktop support demonstrated. |

Loader source work is excluded: current [Hoolock m1n1 AGENTS.md](https://github.com/HoolockLinux/m1n1/blob/idevice/AGENTS.md) says “The maintainers of this project forbid any usage of AI or LLM tools whatsoever due to legal reasons.”
No loader source was modified, built, forked or copied to work around that restriction. Use previously published permitted binaries; source inspection for a new loader change requires an appropriate non-AI workflow.
